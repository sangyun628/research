LLM Multi-Token Prediction
다중 토큰 예측, 쉽게 이해하기

LLM은 원래 "다음 한 토큰"만 예측한다. MTP는 "앞으로 올 여러 토큰을 한 번에" 예측하게 만드는 기법으로 — 학습 더 똑똑하게, 추론 더 빠르게 만든다.

~3×이론적 추론 가속 (Meta MTP)
1.8×실측 throughput (DeepSeek-V3)
+12~17%코드 벤치(HumanEval/MBPP)
~85%2번째 토큰 채택률(acceptance)

01배경지식 — LLM은 어떻게 글자를 만드나

MTP를 이해하려면 먼저 "보통 LLM이 어떻게 생성하는지"를 알아야 한다.

① 토큰(token)과 자기회귀(autoregressive) 생성

LLM은 글을 토큰(단어 조각) 단위로 다룬다. 생성은 한 번의 forward pass(모델 연산 1회)당 토큰 1개를 뽑는 식으로 진행된다. 지금까지의 토큰 t₁…tₙ을 입력해 tₙ₊₁의 확률분포를 구하고, 하나를 골라 뒤에 붙이고, 다시 전체를 넣어 다음을 구한다. 이 "다음 토큰 맞히기"가 Next-Token Prediction(NTP)이다.

핵심 병목: 토큰 10개를 만들려면 forward pass를 10번 해야 한다. 그런데 디코딩은 메모리 대역폭에 묶인(memory-bound) 작업이라 — 거대한 모델 가중치를 GPU 메모리에서 읽어오는 시간이 대부분이고, 정작 연산 유닛은 놀고 있다. "1회 연산에 1토큰"은 GPU를 충분히 못 쓰는 셈.

② 학습은 사실 "병렬"인데, 생성만 "순차"다

학습(training) 때는 teacher forcing으로 문장 전체의 모든 위치를 한 번에 예측한다(정답을 알고 있으니까). 반면 생성(inference)은 정답이 없어 한 토큰씩 순차로 갈 수밖에 없다. → "학습의 병렬성을 생성에서도 어떻게든 살릴 수 없을까?"가 MTP·speculative decoding의 출발점이다.

02MTP란 무엇인가

Multi-Token Prediction(MTP) = 각 위치에서 다음 1개가 아니라 다음 n개의 토큰을 동시에 예측하도록 모델을 만드는 것.

구현은 보통 공유 트렁크(Transformer 본체) + 여러 개의 출력 헤드 형태다. 트렁크가 만든 하나의 hidden state에서, 헤드 1은 tₙ₊₁, 헤드 2는 tₙ₊₂ … 식으로 각자 미래 토큰을 예측한다.

학습 이득

① 더 똑똑해진다

미래 여러 토큰을 맞히도록 강제하면 — (1) 학습 신호가 촘촘해져 데이터 효율↑, (2) 모델이 앞을 내다보고(pre-plan) 내부 표현을 만들게 되어 멀리 보는 능력↑. 특히 코드·수학처럼 "다음 몇 개를 미리 계획"해야 하는 과제에서 이득이 크다 (HumanEval/MBPP +12~17%).

추론 이득

② 더 빨라진다

추가 헤드들이 미래 토큰을 미리 "초안(draft)"으로 내놓으면, 본 모델이 그걸 한 번에 검증해 맞는 만큼 받아들인다(self-speculative decoding). → forward pass 1회로 여러 토큰을 확정 → 최대 ~3× 가속. 출력 품질은 그대로(lossless).

한 줄로: MTP는 "다음 한 글자만 보던 모델에게 앞을 몇 글자 더 내다보게 가르치는 것" — 그 부수효과로 더 잘 쓰고, 더 빨리 쓴다.

▶인터랙티브 데모 — NTP vs MTP, 같은 문장을 누가 빨리 쓰나

왼쪽은 보통 모델(한 번에 1토큰), 오른쪽은 MTP(한 번에 4토큰 제안 후 검증). 같은 문장을 만드는 데 forward pass(연산 횟수)가 얼마나 차이 나는지 보세요.

두 방식이 만들어내는 결과 문장은 완전히 동일합니다.

03어떻게 동작하나 — 아키텍처 3가지

같은 "다중 토큰 예측"이라도 구현이 다르다. 탭으로 비교해 보세요.

Meta MTP (병렬 헤드)
DeepSeek-V3 (순차 모듈)
Medusa / EAGLE

병렬 독립 헤드 (Gloeckle et al., Meta 2024)

공유 Transformer 트렁크→ hidden h Head 1 → tₙ₊₁Head 2 → tₙ₊₂ Head 3 → tₙ₊₃Head 4 → tₙ₊₄

하나의 hidden state h에서 n개(보통 4) 헤드가 병렬로 각 미래 토큰을 예측. 학습 손실 = 4개 위치 cross-entropy의 합. 추론 때는 헤드를 버리고 일반 모델로 써도 되고(학습 이득만 챙김), 헤드를 draft로 써서 self-speculative 가속도 가능.

메모리 절약 트릭: 헤드별 손실/그래디언트를 순차로 계산해 logit 텐서가 동시에 메모리에 안 쌓이게 한다.

순차 MTP 모듈 (DeepSeek-V3, 2024)

메인 모델 → tₙ₊₁⊕ 임베딩 MTP 모듈(Transformer 블록 1개) → tₙ₊₂

DeepSeek-V3는 인과 사슬(causal chain)을 유지한다. 메인이 tₙ₊₁을 예측하고, 그 결과를 다시 입력에 합쳐 MTP 모듈(자체 Transformer 블록 + 공유 임베딩/출력헤드 + projection)이 tₙ₊₂를 예측. 깊이 D=1(즉 2토큰 지평).

  • 671B 모델에 약 +14B 파라미터(대부분 학습 전용).
  • 주 목적은 학습 신호 강화 — 본 추론 시 MTP 모듈을 버려도 본체 성능이 향상돼 있음.
  • 원하면 그 모듈을 그대로 speculative decoding의 draft로 재활용 → 2번째 토큰 채택률 ~85% → throughput ~1.8×.

사후 부착형 draft 헤드 (Medusa / EAGLE)

이미 학습된 모델에 가속 전용 draft 모듈만 추가로 붙이는 계열. (모델 자체를 MTP로 사전학습하지 않아도 됨)

동결된 본 모델 hidden→ Medusa: 여러 MLP 헤드(병렬) EAGLE: feature 수준 자기회귀 draft
  • Medusa: 마지막 hidden에 MLP 헤드 여러 개를 얹어 미래 토큰들을 병렬로 초안 + 트리 어텐션으로 여러 후보 동시 검증.
  • EAGLE: hidden(feature) + 직전 토큰을 함께 써서 자기회귀적으로 초안 → draft 정확도↑(현재 SOTA, vLLM·SGLang·TensorRT-LLM 채택). 단 k토큰에 k번 순차 패스가 필요(P-EAGLE이 병렬화 시도).

04추론 가속의 핵심 — Self-Speculative Decoding

MTP가 "빠른" 진짜 이유. 그리고 왜 품질이 안 떨어지는지(lossless).

일반 speculative decoding

원래 speculative decoding은 작고 빠른 별도 draft 모델이 토큰 k개를 싸게 제안 → 크고 느린 target 모델이 그 k개를 한 번의 forward pass로 병렬 검증 → 맞은 접두부(prefix)까지 채택하고 틀린 지점부터 다시. 검증은 수학적으로 target 분포를 그대로 보존(rejection sampling)하므로 결과 품질이 동일하다.

MTP의 한 끗: 별도 draft 모델이 필요 없다. 모델 자신의 MTP 헤드/모듈이 draft 역할을 한다(self-speculative). → 두 모델 정렬 문제·운영 부담 없음.

채택(acceptance) 규칙 — 왜 lossless인가

draft 토큰을 받아들일지는 난수 U~[0,1)를 뽑아 P_target / P_draft ≥ U이면 채택, 아니면 거절하고 그 자리에서 target 분포로 보정 샘플링. 이 규칙 덕분에 최종 출력 분포 = 원래 모델 분포가 수학적으로 보장된다.

▶인터랙티브 데모 — draft → verify → accept 한 스텝씩

MTP가 4개 토큰을 초안(보라)으로 제안하면, 본 모델이 검증해 맞는 접두부는 채택(초록), 처음 틀린 곳부터는 거절(빨강)한다. "다음 스텝"을 눌러 한 사이클씩 진행해 보세요.

06장단점 · 언제 쓰나

장점

  • 이중 이득: 학습 신호 강화(품질) + self-speculative(속도).
  • Lossless: 검증 규칙이 원본 분포를 보존 → 정확도 손실 없음.
  • 별도 draft 모델 불필요: 운영·정렬 부담 감소.
  • 코드·수학·구조화 출력에서 특히 효과적(look-ahead 과제).

단점·주의

  • 학습 비용/복잡도↑: 추가 헤드·모듈, 손실 설계.
  • 가속은 채택률에 좌우: 도메인이 어렵거나 다양하면 α↓ → 이득↓.
  • 배치 크기 영향: 대형 배치(이미 compute-bound)에선 가속 효과가 작아질 수 있음.
  • 품질 이득은 도메인별: 일반 자연어보다 코드·수학에서 크다.
언제 유용한가: ① 단일/저배치 저지연 서빙(챗봇·코딩 어시스턴트)에서 토큰 지연을 줄이고 싶을 때, ② 새 모델을 사전학습하며 코드/추론 품질과 추론 효율을 동시에 노릴 때. 반대로 이미 처리량 포화(대배치 오프라인)면 가속 이득은 제한적.

07생태계 — 어디서 쓰나

  • DeepSeek-V3 / R1: 사전학습에 MTP 목표 채택, 추론 시 speculative decoding으로 재활용.
  • Meta (Gloeckle et al. 2024): "Better & Faster LLMs via Multi-token Prediction" — n=4 헤드, 코드 강세 + 3× 추론.
  • 서빙 엔진: vLLM · SGLang · TensorRT-LLM이 MTP/EAGLE/Medusa 기반 speculative decoding을 1급 기능으로 지원.
  • 후속 연구: FastMTP, P-EAGLE, self-distillation MTP, 확률회로 기반 MTP 등 — draft 정확도·병렬성 개선이 활발.
큰 그림: MTP는 "next-token 한 칸"이라는 LLM의 오래된 기본 가정을 흔든 흐름의 중심에 있다. 학습 목표(품질)와 추론 메커니즘(속도)을 동시에 건드린다는 점에서, 단순 최적화를 넘어 LLM 설계 패러다임의 한 갈래로 자리잡는 중.

08핵심 정리

  1. 보통 LLM = 다음 1토큰 예측 → 생성이 forward pass 1회당 1토큰이라 느리다(메모리 바운드).
  2. MTP = 다음 n토큰을 동시에 예측하도록 학습(공유 트렁크 + 다중 헤드/모듈).
  3. 학습 신호가 촘촘 + 앞을 내다봄 → 품질↑(코드/수학 특히).
  4. 추론 자기 헤드가 draft → 본 모델이 한 번에 검증·채택(self-speculative) → 속도↑, 품질 동일(lossless).
  5. 가속비는 채택률 α에 좌우. DeepSeek-V3 실측 ~1.8×, 이론 상한 ~3×.
  6. 친척: Medusa(병렬 MLP 헤드), EAGLE(feature 자기회귀, 현 SOTA) — 사후 부착형 가속.
