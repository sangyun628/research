PROMPT ARCHITECTURE PATTERNS IDENTIFIED
==============================================================================

Pattern 1: Hierarchical Prompts
  ├─ Level 1: Main system prompt (global behavior)
  ├─ Level 2: Sub-agent prompts (specialized roles)
  ├─ Level 3: Tool descriptions (specific actions)
  └─ Level 4: System reminders (dynamic adjustments)

Pattern 2: Dynamic Reminder Injection
  • <system-reminder> tags injected mid-conversation
  • Updates on: date, permissions, available tools, status changes
  • Purpose: Prevent LLM from forgetting earlier system prompt in long conversations

Pattern 3: Meta-Prompting
  • User writes rules → System evaluates rules with a meta-prompt
  • Example: auto-mode CRITIQUE_SYSTEM_PROMPT evaluates user allow/deny rules
  • Enables AI-assisted rule validation

Pattern 4: Role & Boundary Setting
  • "You are X" (role definition)
  • "You're not Y" (role boundary)
  • "Don't Z" (forbidden actions)
  • Purpose: Prevent role confusion, clarify responsibilities

Pattern 5: Structured Evaluation Criteria
  • Always broken down into numbered/bulleted items
  • Example: Clarity, Completeness, Conflicts, Actionability
  • Ensures consistent application of rules

   → Numbered criteria improve consistency

   → Let LLM evaluate user-provided rules/instructions

5. Build hierarchical prompt system
   → Main prompt + sub-agent prompts + tool descriptions

6. Plan for token efficiency
   → Deferred tool loading, dynamic reminders, compression

   → Auto-mode: separate LLM call for approval decisions
